# Contributing

Спасибо за интерес к проекту. Ниже — правила, по которым живёт кодовая база.
Они обязательны и проверяются в CI.

## Запуск

```bash
npm ci
npm run dev:web      # http://localhost:5173
npm run dev:server   # http://localhost:3000 (второй терминал)
```

Для реального ИИ скопируйте `.env.example` в `.env` и заполните
`YANDEX_API_KEY` / `YANDEX_FOLDER_ID`. Без ключей сервер работает в dry-run.

## Правила разработки

1. **Test-Driven Development.**
   Сначала тесты — потом код. Если тест падает, исправляется код, а не тест.
   Ослаблять или удалять тест, чтобы «позеленело», нельзя: если тест неверен,
   это обсуждается отдельно.
2. **Тесты обязаны покрывать** граничные случаи, некорректный ввод и
   защищённые сценарии: суммы, даты договора, плейсхолдеры, гарантии
   обезличивания.
3. **Приватность — часть архитектуры.** Браузерный код никогда не отправляет
   исходный текст документа на сервер: только обезличенный. Формулировки в
   документации и на лендинге должны это отражать — **персональные данные**
   не покидают устройство, а не «документ» (проверяется `npm run check:copy`).
4. **Персональные данные** в тестах и корпусах — только вымышленные
   (`info@example.com`, «Ромашка», `+7 900 000-00-00`).
5. **Строгий TypeScript.** `any` запрещён; исключение допускается только с
   комментарием, объясняющим необходимость.
6. **Код:** маленькие функции, без дублирования, повторное использование
   существующих реализаций. Комментарии и сообщения коммитов — **на
   английском**; документация для пользователей — на русском.
7. **Никаких секретов в репозитории.** Только `.env` (в `.gitignore`) и
   `.env.example`; проверка — `npm run check:secrets`.

## Перед PR: гейты

```bash
npm run typecheck
npm run lint
npm test            # 148 unit-тестов
npm run test:e2e    # 10 сценариев Playwright
npm run check:secrets
npm run check:copy
npm run audit       # аудит маскирования на утечки ПДн
```

## Коммиты

Формат: `type(scope): короткое описание в императиве` (`feat`, `fix`,
`chore`, `refactor`, `test`, `docs`). Один коммит — одна логическая правка.
Хуки (husky + lint-staged) прогоняют ESLint и Prettier на изменённых файлах.

## Структура

| Путь              | Назначение                                                |
| ----------------- | --------------------------------------------------------- |
| `packages/masker` | маскирование ПДн и извлечение текста (чистый TS)          |
| `apps/web`        | лендинг и инструмент в браузере (Vite)                    |
| `apps/server`     | NER-предохранитель, вердикт-движок, мок-платежи (Fastify) |
| `e2e`             | сквозные сценарии пользователя (Playwright)               |
| `scripts`         | извлечение, аудит утечек, бенчмарк, QA, проверки          |

## Сообщения об ошибках

Опишите: что произошло, где (модуль/функция), при каких условиях, что
ожидалось и что получилось фактически. Для приватности — воспроизводите на
вымышленных данных.
